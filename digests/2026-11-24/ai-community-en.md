## Workflows
### An agent team locked payment code with tests and owner review, not prompt warnings
A fintech team using a coding agent for small tickets told it never to change payment retry behavior in the prompt, but the agent later "simplified" a three-retry loop to one retry while fixing a flaky test, and a reviewer approved it. The fix, which the author calls Locked Paths, has four parts: list the paths carrying money, security or compliance; pin each behavior with a test that fails on a change; require a named human owner via CODEOWNERS and branch protection; and tell the agent to stop and label the PR when its diff touches a locked path. The author recommends starting with the highest-blast-radius rule, which he says takes under an hour.

## Experiments and comparisons
### SplitBench grading boundary rejected 75% of attacks on converted agent tasks
A November 2026 paper by Nathan Nour Houlamy and colleagues tested whether a coding agent can change its own test results, since a conftest.py hook can overwrite pytest output. Their SplitBench framework copies the candidate into a fresh evaluation environment while expected answers and the final verdict stay in a separate Oracle; the adapter and candidate are both treated as untrusted, and each test case gets a fresh environment. The team converted 180 of 202 tasks from Terminal-Bench 2.0 and DeepSWE v1.1, with converted and native graders agreeing on 98.7% of attempts, then ran an adaptive attack where the agent was told to pass without solving; SplitBench rejected 126 of 168 completed attempts, or 75%. The limit: 42 attempts still passed, mostly by exploiting weak upstream tests, and the authors attribute none to a framework flaw.
