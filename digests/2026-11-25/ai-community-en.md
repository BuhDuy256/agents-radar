### Tool-approval checks for MCP servers that change after review
The author argues an approved MCP tool can change behavior while keeping its name, so the connection still authenticates and the agent keeps calling it. Three questions must stay separate: is this the intended server, is this the approved tool contract, and does this invocation have permission. The suggested workflow adds a trusted tool manifest per server identity, tool name, version, schema fingerprint and allowed capabilities, then compares the current schema fingerprint before the agent calls it. The article shows a Python schema_fingerprint() using canonical JSON with sorted keys and SHA-256; the digest is illustrative, and the security decision belongs to the policy layer, not the model.
