## Workflows
### Build a browser study app that answers only from your own notes
The author built Grading Buddy, an offline study app that runs Liquid AI's LFM3-1.7B in the browser and answers only from notes she has checked. The stack is Transformers.js, the ONNX export of LFM3-1.7B at `q4f16` (about 1.1 GB), and WebGPU; the model runs in a Web Worker so the page stays responsive. The app matches the question to a topic, returns early if nothing matches, passes that topic's facts to the model, then requires a grounding check and a required-facts check to pass. If either check fails, it shows the note card instead. So far the author has only used this in Taekwon-Do study, and on the minimal version the model got Chon-Ji wrong.

## Experiments and comparisons
### 89.6% of 37,383 remote MCP servers answered a daily connectivity check
NestDaddy connected to every remote MCP server in the official registry the way an MCP client does — sending `initialize`, `notifications/initialized`, then `tools/list` — with no credentials and a 10-second timeout, running daily from one server in Europe. Of 37,383 remote servers, 33,496 (89.6%) answered; 12,447 returned 401 or 403, which the authors counted as live but key-required, so their tools were not visible. Common failures were connection errors (1,156) and HTTP 404 (997). The median `initialize` took about 500 ms, measured from a single location, so the authors treat the timings as a rough guide rather than a ranking. The registry listed 62,377 entries, of which the authors hid 7,839 (12.6%) as spam.
Source: [dev.to](https://dev.to/nestdaddy/we-tested-37000-mcp-servers-heres-how-many-actually-work-1pne)

### Gemma 4 31B through a free API, on a local chat page and a small ADK agent
The author built a chat page, a terminal client and a small ADK agent against Gemma 4 31B served through AMD Token Lab, the AI Developer Program's OpenAI-compatible API. A new key came with 10 points for a 30-day period (extendable once by 15 days) and a limit of 20 requests per minute. The chat page is standard-library Python, serves one page on `127.0.0.1` and forwards `/v1/*` to the base URL with the key attached, so the key never reaches the browser. In the author's run, 23 requests used 0.000335 of the 10 points; one reply took 4.96 s to its first token and decoded at 9.5 tokens per second.

### One-pass probabilities compared with four generative models on 48 support tickets
The author benchmarked the Gemini Decisions API, which scores a fixed set of allowed answers in one forward pass and returns probabilities, against Gemini 3.8 Flash, Gemini 4 Hydrogen, Gemini 3.5 Flash-Lite and Gemma 4 E2B on a laptop CPU. All five backends received the same three triage questions; the generative models answered via a prompt plus a JSON schema limiting replies to allowed answers. Per the author, clear tickets scored 0.93 to 1.00 on team confidence, a ticket mixing a crash with four charges split 0.58 billing against 0.39 technical and was flagged for review, and the two urgency misses were the two lowest urgency confidences at 0.699 and 0.663. The raw rows are in the repository.
