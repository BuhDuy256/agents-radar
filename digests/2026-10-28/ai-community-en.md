## Workflows
### Plugin blocks an AI agent from saying "done" until tests pass
Wageesha Tripathi built the free, MIT-licensed **proof-of-done** Claude Code plugin because agents like Claude Code, Codex and Cursor often report a fix without running tests, or hide failures behind pipes such as `| tail`. The plugin records every code edit and every test, build or lint run with its exit code, detects project commands across npm, pytest, Go, Cargo, Maven and others, and blocks the stop when there is no run after the last edit or the last run failed. It also rejects hidden exit codes, runs where zero tests executed, flaky passes and test tampering such as `.skip` or weakened assertions. Install via two commands inside Claude Code.

## Experiments and comparisons
### Trajectory-level token accounting moved the top cost off the model in 9 of 11 agents
TokenLat instrumented 11 production agents with per-step token attribution tagged by trajectory rather than by request, then ranked steps by cost per resolved task instead of mean cost per call. In 9 of the 11, the model was not the most expensive step: embedding/retrieval loops led in 5, PII/guardrail models in 3. One "free" embedding step at $0.00002 per call ran up to 180 times in a re-planning loop, reaching $0.0036 per task against $0.0028 for the single LLM completion. The author's fix is a `cost_per_resolved_task` SLO and routing each step to a right-sized model.
Source: [dev.to](https://dev.to/tokenlat/we-instrumented-11-production-agents-with-real-token-accounting-in-9-of-them-the-most-expensive-mgb)

### A MoE model 3x faster than dense failed every multi-step phase
The author ran Ornith 1.0 35B (MoE, 35B/A3B) against dense Qwen3.6 27B on a home RTX 5090 through opencode. Ornith matched or beat it on one-shot work — 14/14 spec implementations in 22s vs 58s, and 9 review findings vs 6 — at 246 tok/s vs 71 tok/s. On a machine-judged RFC 6902 port to Rust, though, Ornith failed all five sessions, once leaking chain-of-thought mid-file and reporting done with code that did not compile. Qwen3.6 finished every phase, reaching 108/112 passing with 4 officially skipped. The author set dense as the default and demoted Ornith to one-shot tasks only.

### Eight models given an open sandbox split into builders and testers
The author gave seven local models plus Claude Code each a Debian container, five tools, 50 actions and no task, five runs each, then had blinded judges label the logs. Builders — Claude, Gemma, gpt-oss — made working projects; Claude left a runnable tool with passing tests in 4 of 5 runs and used a median of 10 actions. Testers — Qwen, Granite — checked each tool once and stopped. Llama 3.1 emitted bursts of up to 98 tool calls without reading results; phi4-mini never called a tool. No run out of 40 tried to leave the container. Most gpt-oss, Qwen, Granite and Ministral runs treated the session as a demonstration.

### Four search APIs tested on 30 agent-style queries, no single winner
Pallavi Singla ran You.com, Tavily, Exa and Parallel live against 30 queries written as agents call search, split across GTM, insurance and finance use cases, three runs each through promptfoo with identical parameters and SimpleQA grading. Parallel scored highest overall at 67% accuracy and won finance; You.com was fastest at 593 ms p50 with zero empty responses; Exa had the best precision@5 (40%) and won insurance; Tavily won a config-docs lookup. All four missed an active binding suspension, and no API got everything right in insurance. The harness, answer keys and MCP server are MIT-licensed.
