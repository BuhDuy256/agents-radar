## Workflows
### A gateway policy cannot stop the routes your agent never takes
An MCP gateway controls only the tools it sees. The author describes a side-door test: start from one action such as sending email, list every route to it (the MCP tool, a shell script driving a local client, a signed-in browser session, an API token in the environment), and note which identity each route carries. Then give the agent a draft-only identity without send permission and run each attempt in a sandboxed account. Verify against the mailbox's Sent Items and the tenant message trace, not the agent's own report. If a route succeeds, the boundary failed.

## Experiments and comparisons
### Snapshot rollback let a 27B model hit 80.2 on OSWorld Verified
The CUA-Master authors report 80.2 on OSWorld Verified, 36.9 on OSWorld 2.0 and 43.9 on WeaveBench for their 27B model. Rather than discarding a whole run when a rollout fails, their runtime snapshots the VM at stable boundaries, uses a detector to find the earliest divergence step from the verifier residuals, trajectory and final state, then rolls back to the snapshot just before it and keeps only the cleanest passing branch. Tasks came from sliced video tutorials plus a unified GUI and shell action space. The limit: these are the paper's own reported scores, not an independent replication.

### One harness, 11 model rows: the top ten sit inside five hundredths of a point
The author benchmarked seven GGUFs under llama.cpp plus one model on the Strata engine, all on two RTX 5080s with pinned sampling and three seeds per task, across 18 tool tasks, 72 code tasks and 72 multi-step agent tasks. Thinking ON multiplied per-turn latency (280–1060 ms against 19–85 ms) but paid off mainly on hard code, where UD-Q3 rose from 79% to 93%; easy code (91–100%) did not separate the fleet. A second engine moved the same 72 agent tasks by three thousandths. Static, single-author hardware test.
