### The author cut an MCP server from 15 tools to 4 and two calls
The author rebuilt a read-only AWS cost-triage MCP server, which first answered "where am I wasting money?" with seven tool calls. The lean version uses four outcome-level tools: `find_waste` runs every check internally, a `Literal` scope parameter blocks garbage input, responses default to five decision fields per finding with `detail=True` for the full blob, and a small `describe_scope()` tool is loaded only on demand. Tool schemas shrank 88% and the same question took two calls. His own numbers, not a provider benchmark. It fits anyone noticing MCP servers slow down as tools accumulate.

### The author moved MCP retries from the spec into his own harness
After a remote MCP tool timed out and his agent carried on as if it had answered, the author searched the spec and found no retry setting. He confirmed MCP only defines `tools/list` and `tools/call`, leaving retry, loop control, memory, and user approval to the host. His fix: retry once on timeout, then pass the error to the model as a failed result. He also notes the 2026-07-28 spec dropped `initialize` and sessions, added a `server/discover` call, and gave `tools/list` results `ttlMs` and `cacheScope` hints for cache refresh.

## Experiments and comparisons
### Terminating schema cuts MCP description poisoning to 7.8% top-1
The author froze 1,312 MCPTox tool descriptions, poisoned them, and had Swallow-8B-AWQ answer single "call the X tool" queries, scored by rules without an LLM judge. Baseline hybrid retrieval followed the payload 13.8% of the time. A schema-only arm that drops all description text fell to 7.8%; an LLM-rewrite arm scored 0.080 with a disclosed shared-model confound. Utility cost was bounded, since the benign-completion proxy confidence intervals overlap baseline for all arms. The author states no arm eliminates poisoning without trade-offs and that a gateway needs canonicalisation plus runtime policy. Adaptive attacks were pre-registered but pending.
