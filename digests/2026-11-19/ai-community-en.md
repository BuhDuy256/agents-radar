### Tool-list size barely moved per-task cost; the middle list cost 41% more
The author sliced 4,310 published runs from the THOL leaderboard by tool-list size on the 17 long tasks where a run burns over 200,000 tokens. Vanilla Claude Code cost 301,467 tokens per solved task, an 8-tool list 294,318, and a 30-tool list 304,341 — all inside the board's roughly 17% run-to-run noise. A 13-tool list cost 425,411 tokens, up 41%, with 5.5 extra turns. The author credits this to poor tool returns forcing fallback re-reading, not list size, and notes the data has no real 200-tool entry and almost every run succeeded.

### Eleven models picked the same tool in 17 of 20 categories, but auth split sharply
The author ran 100 unnamed build tasks twice through Claude Sonnet 5.5, GPT-5.6 Terra and Gemini 3.1 Pro (30 answers per category), then through eight open-weight models (80 per category), counting only what was installed. ### One script per turn cut tokens 98.7% in the company's MCP test but hid runtime values from the classifier
Code Mode lets Claude write one JavaScript program that makes many tool calls, so only what the code returns reaches the model, instead of one call and result per turn. Anthropic's MCP research measured tool definitions and results at 150,000 tokens through context, cut to 2,000 with the work moved into code, according to the author. In auto mode the classifier reviews the script, not the runtime values, so a path computed from a search result is never seen; rule or hook coverage is needed. The feature is experimental, JavaScript-only, and unavailable on Bedrock, Vertex, gateways, and custom base URLs.
